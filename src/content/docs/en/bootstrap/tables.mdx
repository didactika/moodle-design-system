A table is for data that has several attributes per row and that people compare. For a list of one thing per line, use a list group.

## When to use it

<div class="ds-do-dont">
<Rule kind="do" title="Use it">

- A header row with short column names; numbers aligned to the right.
- Highlight the row under the pointer (`table-hover`) when rows are actionable.
- Wrap wide tables in `table-responsive` so the page never scrolls sideways.
- Keep the actions of a row in the same place and always visible.

</Rule>
<Rule kind="dont" title="Don't">

- Use a table for layout.
- Colour rows without a text that says why.
- Hide columns that are needed to understand the row.

</Rule>
</div>

## Anatomy

A `table` with a **caption**, a **header** (`thead`, `th scope="col"`) and a **body** (`tbody`) whose first cell can be the **row header** (`th scope="row"`). Rows and cells can take a contextual colour.

### Sortable headers

A sortable header is a button inside the `th`. Only one column is sorted at a time, and the `aria-sort` of its `th` (`ascending`, `descending` or `none`) says which: the icon of the sorted column is in the primary colour and fully opaque, the others are dimmed until the pointer or the keyboard reaches them. The second table shows each state next to the others.

## Combinations

| Combination | Use it for |
|---|---|
| Table × toolbar | Search and filters on the left, the main action on the right; the toolbar sits inside the same card as the table. |
| Table × selection | A checkbox column; when rows are selected a bar shows how many and the actions that apply to them. |
| Table × row actions | Icon buttons at the end of the row (edit, hide, delete), always visible, never hidden until hover. |
| Table × pager | The pager of a list in the foot: rows per page, range and arrows. |
| Table × status | A soft badge with a dot for the state of each row. |
| Compact × people | Small padding, an avatar with a name, a role in a badge and a thin progress bar. |

## What Didactika changes and why

| What we changed | Why it helps |
|---|---|
| Full width, a small capital header and quiet lines | The header is a label, not a title; the eye goes to the data. |
| The actions of a row are always visible | Hiding them until hover makes them invisible on touch screens and for keyboard users, and moves the layout. |
| The selected row is tinted | It is clear what an action will apply to before it is pressed. |
| The toolbar, the table and the pager are one card | They are one object; the user sees one thing to work with. |
| Sortable headers are buttons with an icon | They announce the order and are reachable by keyboard. |

## Classes

| Class | What it does |
|---|---|
| `table` | Base |
| `table-striped`, `table-hover`, `table-bordered` | Stripes, row hover and borders |
| `table-sm` | Compact |
| `table-active`, `table-success`… | Colour of a row or cell |
| `table-responsive` | Scrolls inside its box on small screens |
| `align-middle` | Vertical alignment |
| `table-toolbar`, `table-toolbar-start`, `table-toolbar-end` | The bar over a table (Didactika) |
| `table-toolbar-selection` | The bar that appears when rows are selected (Didactika) |
| `table-select` | The narrow column of the checkbox (Didactika) |
| `table-actions` | The cell with the actions of a row (Didactika) |
| `table-sort` | A sortable header (Didactika) |
| `table-foot` | The foot of a table, for the pager (Didactika) |

## Accessibility

- Use `th` with `scope`, and a `caption` (it can be visually hidden).
- Do not use a table for layout.
- A coloured row also says it with text.
- Sortable columns announce the order (`aria-sort`).
