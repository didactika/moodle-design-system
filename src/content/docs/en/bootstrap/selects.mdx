A select lets the user pick one option (or several) from a short, known list. It is the theme's own select: native behaviour, with the height, border and arrow of the other fields.

## When to use it

<div class="ds-do-dont">
<Rule kind="do" title="Use it">

- A select for 4 to about 15 options that the user already knows.
- A visible label, linked with `for` and `id`.
- A first option that says what to do ("Choose…") when no value is the default.
- `multiple` with `size` only when the user must see the options at once.
- Moodle sizes a select to its content; add `w-100` where it has to fill the row.

</Rule>
<Rule kind="dont" title="Don't">

- Use a select for two options; use [radio buttons](../checks/) or a switch.
- Use it for a long or searchable list; Moodle's autocomplete is the component for that.
- Style the options; the browser draws them.
- Change the arrow or the height in a plugin.

</Rule>
</div>

## Anatomy

A select has a **label**, the **control** with the chosen option and an **arrow**, and the **list** the browser opens. Same hint and message rules as a [text field](../form-controls/).

## Variants and states

### The list that opens

The browser draws the list of a select on its own and a page cannot style it. In this system a select opens a menu of the design system instead: the same one a dropdown has, with the groups as headers, the disabled options dimmed and the chosen one marked. The select keeps its value and its events, so the markup of a plugin does not change. Try it with the keyboard too (arrows, Home, End, a letter, Enter, Escape).

<Example title="The menu of a select" src="selects/menu" />

### Sizes

<Example title="Small, default and large" src="selects/sizes" measure="Height,Padding,Font size,Line height,Radius,Border" />

Use the default size. Small belongs in dense places (a filter bar over a table, the rows per page of a pager); large only for a single main field on a page.

## Several values as tags

A select with the attribute `multiple` is drawn as a field of tags: what is chosen shows as pieces that are removed one by one, and the options open in the menu of the design system, with a check, which stays open while the user picks. The select underneath keeps its values and its events, so the markup of a plugin does not change. The same field also takes free text (tags that do not exist yet); see the page "Tags".

## Combinations

| Combination | Use it for |
|---|---|
| Select × a few options | 4 to about 15 options the user already knows. Fewer than 4: radios. More than 15, or searchable: the autocomplete of Moodle. |
| Select + optgroup | Group options with `optgroup`; the menu shows each group as a header. |
| Select + input group | A select attached to a button ("Hide | Apply"): the group joins them into one control. |
| Width | Moodle sizes a select to its content. Add `w-100` where it has to fill the row. |

## What Didactika changes and why

| What we changed | Why it helps |
|---|---|
| The list that opens is a menu of the design system | The native list cannot be styled, so each browser showed a different, plain list that did not match the rest of the page. One menu looks the same everywhere and shows the chosen option. |
| The arrow has its own room on the right | Long options never run under the arrow, in any size. |
| Same height, border and focus as a text field | A select next to a field looks like its sibling, not like another component. |

## Accessibility

- A label for every select.
- Do not use `onchange` to navigate or submit; give a button.
- Native keyboard behaviour (arrows, type to find) is free: keep the native element.
- An error message is linked with `aria-describedby`.
