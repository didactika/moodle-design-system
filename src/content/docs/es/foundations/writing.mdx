El texto de la interfaz es parte del diseño: un botón claro ahorra una consulta al soporte. Estas reglas valen para todos los plugins, en español y en inglés.

## Reglas

- **Un botón dice lo que hace**, con un verbo y, si hace falta, el objeto: "Guardar cambios", "Eliminar 3 cursos". Nunca "Aceptar", "Sí" o "Enviar".
- **Un título dice qué hay aquí o qué se pide**, en minúscula salvo la primera letra, sin punto final.
- **Un error dice qué pasó y cómo arreglarlo**, junto al campo, sin culpar: "Usa letras, números y guiones" y no "Valor no válido".
- **Un estado vacío dice qué falta y qué hacer**, en dos líneas cortas como máximo.
- **Una confirmación nombra lo que se perderá**, y su botón repite la acción ("Eliminar curso").
- **Números, fechas y unidades siguen el idioma de la página** y se escriben igual en toda la pantalla.
- **No grites**: ni mayúsculas para enfatizar, ni signos de exclamación, ni emoji en mensajes del sistema.

## Antes y después

| En vez de | Escribe |
|---|---|
| Aceptar / Cancelar | Eliminar curso / Cancelar |
| Error: entrada no válida | El ID del curso no puede tener espacios. |
| Sin datos | Aún no hay cursos. Crea uno o importa una copia. |
| ¿Seguro? | ¿Eliminar 3 cursos? También se borran sus calificaciones. |
| Enviar | Crear curso |
| Operación completada con éxito | 3 cursos eliminados. Deshacer |

## Dónde va el texto

| Pieza | Longitud | Tono |
|---|---|---|
| Botón | 1–3 palabras | Imperativo |
| Etiqueta de campo | 1–4 palabras | Un sustantivo, no una pregunta |
| Ayuda bajo un campo | Una línea | Qué se permite, con un ejemplo si ayuda |
| Alerta | Una o dos líneas | Qué pasó y luego qué hacer |
| Toast | Una línea | El resultado; una acción solo si se puede deshacer |
| Título de un diálogo | Una pregunta o una acción | Las mismas palabras que el botón que lo abre |
