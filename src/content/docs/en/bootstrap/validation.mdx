A field in error changes its border and shows a message under it. The colour is a reinforcement: the message is what tells the user what is wrong and how to fix it.

## When to use it

<div class="ds-do-dont">
<Rule kind="do" title="Use it">

- `is-invalid` with an `invalid-feedback` that says what to do ("Enter a valid email address").
- Validate when the user leaves the field or sends the form, not on every key.
- `is-valid` only when confirming helps (a free short name); do not mark every field.
- Link the message with `aria-describedby`.

</Rule>
<Rule kind="dont" title="Don't">

- Show the state with colour alone.
- Write "Invalid value" or an error code.
- Clear what the user typed when it is wrong.
- Show the message far from the field.

</Rule>
</div>

## Anatomy

A field in error has its **control** with the state class, and under it the **message** (`invalid-feedback`), in the same group as the label. Checkboxes show the message under their label.

## Classes

| Class | What it does |
|---|---|
| `is-invalid`, `is-valid` | State of a control |
| `invalid-feedback`, `valid-feedback` | Message under the control; shown when the control has the state |
| `was-validated` | On the form: states follow the browser's own validation |

## Accessibility

- The message is text, not only a colour or an icon.
- `aria-invalid="true"` on a field in error.
- After sending, move the focus to the first error.
- A summary at the top of a long form lists the errors with links to the fields.

## Used in

Every Moodle form; the import dialogs of FileBank and servicemanager.
