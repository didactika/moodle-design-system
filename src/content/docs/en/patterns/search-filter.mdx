People find things in two ways: by typing what they remember and by narrowing a list. This pattern combines both in one row above the list, so the person sees at a glance what narrows the list and how to undo it.

## When to use it

- The list is long enough that scrolling is not a way to find something (more than about twenty items).
- Use only the search for a list with one obvious thing to type.
- Use only [filter chips](../../didactika/filter-chips/) when the list has a single filter with two to four values and nothing else to narrow it (for example the activity types that are on or off). Chips are never mixed with filter menus in the same toolbar.

## Anatomy

1. **Search field** (`dd-searchbox`): the magnifier inside a round field, at the start of the row.
2. **One menu for each filter**, beside the search: status, course, activity, group, dates. Each menu has the shape of a select and says what it filters ("Status", "All groups", "Grading date").
3. **The button that clears every filter**, an icon button with the reload icon at the end of the row (`table-toolbar-end`), disabled while nothing narrows the list.
4. **The results**, as a table (to work) or as a list (to choose), with the count in the pager under them.

## A menu that filters

- **The base state is not an option.** "All groups", "All the students" or "Every status" is what the menu says while nothing is chosen; it never appears again inside the list of options.
- **A chosen value is shown and tinted.** The menu says what it is narrowed to ("Status: Pending", "Group A") with the primary border and the soft primary background.
- **The arrow becomes a cross.** Once a value is chosen, the arrow of the menu is replaced by a cross (`dd-select-clear`) that takes the filter back to its base state. The cross has its own label ("Clear: Status").
- **Counts go inside the menu.** When the values of a filter have counts, each option shows its count, computed with the other filters applied.
- A filter with several values (status) uses checkboxes inside the menu; a filter with many values (course, activity) has a search field at the top of its menu.

## One row, always

The toolbar never breaks in two rows. The search shrinks down to its own room (10 rem) and the filter menus keep their width beside it; a chosen menu says only its value ("Graded by a teacher", not "Status: Graded by a teacher") and ends with an ellipsis before its cross when it is too long: the text never runs under the cross. The menu is a block (`button.dd-select`), because only a block cuts its text with an ellipsis. When the menus do not fit, on a narrow screen or with long values, they are grouped in one menu, **Filters (2)**, always with the funnel icon (`i/filter`), which says how many filters are applied and holds the same menus one under the other; they come back to the row when there is room again.

## Behaviour

1. Search runs when the user stops typing (300 ms); Enter does not submit the page.
2. Every filter applies at once and the list goes back to its first page.
3. The cross of a menu clears that filter only; the button at the end of the row clears the search and every filter.
4. The counts of the options are the counts **with the other filters applied**, so an option never promises results that are not there.
5. With no results, the list shows the empty state of a search, with its icon and the way to clear the filters.
6. Every filter goes to the address, so the search can be shared and survives a reload.

## Layout and spacing

| Between | Distance |
|---|---|
| Search and the first menu | 0.5 rem |
| Menus | 0.5 rem |
| Menus and the clear button | The rest of the row: the button sits at its end |
| Toolbar and results | 0, a hairline separates them inside the same card |

## States

| State | What the user sees |
|---|---|
| Searching | The results dim and keep their height; the field keeps its focus |
| No results | The empty state of a search, with its icon and a "Clear filters" button |
| Error | An alert that keeps the filters and offers "Try again" |

## Narrow screens

The search takes the whole width; the menus wrap below it; the clear button stays at the end of the first row.

## Accessibility

- The search has `role="search"` and a label on the field.
- Each menu is a button with `aria-haspopup` and `aria-expanded`; its label names the filter.
- The cross of a menu and the clear button name what they clear.
- The count of results is a `role="status"` region.
